# Safe network rollout

This is a **two-phase** workflow. Phase 1 is local to this repo (`safe-network-config`). Phase 2 happens inside a clone of the network's public Safe wallet fork. Same skill covers both, because new networks, logo updates, and staging fixes all touch the same files.

When triggered, ask the user for any of these missing arguments before starting:

| Argument | Example | Source |
| --- | --- | --- |
| network id | `linea`, `cronos`, `<new-id>` | matches `networks/<id>/`, `TEMPLATE_ID`, and the wallet branch suffix |
| brand name | `"Linea Safe"` | shown in webmanifest and as the page title |
| gateway URL | `https://gateway.staging.safe.<network>.com/` | their staging client gateway |
| wallet fork repo | `git@github.com:<org>/safe-wallet-web.git` | usually the network team's fork of safe-global/safe-wallet-monorepo |
| brand color | `#38ff9c` | non-dark stop of the brand gradient, or the solid brand color |
| source SVGs | `logo-wo-text.svg` (icon) + `logo-w-text.svg` (lockup) | from designer, network team's site, or their own wallet fork |

If the user is **updating** an existing network rather than adding one, skip Phase 1 steps that already exist (e.g. don't re-run the asset generator) and jump to whichever step needs to change.

## Phase 1 — network configuration in this repo

Working directory: this repo (`safe-network-config`).

### 1.1. Place source SVGs in repo root (gitignored)

```bash
cp <icon-only-svg>  logo-wo-text.svg
cp <full-lockup-svg> logo-w-text.svg
```

If the network has a public wallet fork that already contains its branding, the easiest source is `apps/web/public/images/logo-round.svg` (→ `logo-wo-text.svg`) and `apps/web/public/images/logo-text.svg` (→ `logo-w-text.svg`) from that fork.

### 1.2. Create `.env` (gitignored)

```env
BRAND_NAME="<Brand Name>"
TEMPLATE_ID="<network-id>"
```

Without these, `generate.js` writes into `networks/generated/`.

### 1.3. Generate assets

```bash
npm install     # only first time per machine
npm run generate
```

Creates `networks/<id>/` with `config.json` (copied from `networks/default/`), `public/safe.webmanifest` (rewritten with `BRAND_NAME`), full favicon set, and the four logo SVGs.

### 1.4. Sanitize the SVGs (do not skip)

Adobe Illustrator-exported SVGs come with two pitfalls — generic gradient IDs that collide when multiple SVGs are inlined, and gradients that fade to near-black (invisible on the wallet's dark sidebar). Symptoms: brand-mark icon disappears in the rendered header; only the brand-name text shows. Run:

```bash
.claude/skills/safe-network-rollout/scripts/sanitize-svgs.sh \
  --network <id> \
  --dir networks/<id>/public/images \
  --brand-color "<#hex>"
```

`--brand-color` is optional but almost always wanted for `logo-text.svg` / `logo.svg`. Read references/svg-pitfalls.md for the why and how to debug a logo that *still* doesn't render after this.

### 1.5. Configure `networks/<id>/config.json`

The autogenerated `config.json` matches `networks/default/` (`IS_LICENSED:true`, no `LOGO_DIMENSIONS`). For most networks that's wrong — start from this conservative shape:

```json
{
  "EIP155": false,
  "SUPPORTED_VERSIONS": ["1.3.0", "1.4.1"],
  "SAFE_UTILS_SUPPORTED": false,
  "IS_LICENSED": false,
  "LOGO_DIMENSIONS": {
    "HEADER": { "H": "40px" },
    "WELCOME": { "W": "200px", "H": "62px" }
  }
}
```

Tune per-network using references/config-schema.md (which fields exist, when to set them, common values per logo aspect ratio). Remember:

- `HEADER.H: 24px` is too small for a wide lockup with an icon — bump to 40px+ or the icon visually disappears.
- Add `WELCOME` dimensions whenever there's an icon — the welcome page renders larger.
- Custom palette? Ship `lightPalette.json` + `darkPalette.json` next to `config.json`; only specify keys that differ from default.

### 1.6. Commit on a feature branch and push

```bash
git checkout -b feat/<id>-network
git add networks/<id>/
git -c commit.gpgsign=false commit -m "feat: <id> network"
git push -u origin feat/<id>-network
```

Don't merge to `main` yet if you also want to do Phase 2 right away — the rollout will pin to this branch. After Phase 2 is verified and pushed, open the PR for `feat/<id>-network` → `main`.

## Phase 2 — roll out to the wallet fork

Working directory: a clean clone of the network's wallet fork. Use a `tmp/` folder under this repo (already gitignored) so the wallet clone stays out of `safe-network-config` history.

### 2.1. Clone the wallet fork

```bash
mkdir -p tmp && cd tmp
git clone <wallet-fork-ssh-url>
cd <wallet-fork-dir>
```

Wallet forks like `<org>/safe-wallet-web` typically don't carry the upstream Safe wallet's release tags — the rollout script adds `safe-global/safe-wallet-monorepo` as `upstream` and fetches the base tag (default `v1.83.3`).

### 2.2. Run the rollout

```bash
.claude/skills/safe-network-rollout/scripts/rollout-wallet-fork.sh \
  --network <id> \
  --gateway "<gateway-url>" \
  --repo-dir "$(pwd)" \
  --snc-branch feat/<id>-network        # only if not yet on safe-network-config@main
```

What it does (mirrors the original `scripts/script.sh` plus four rollout-time fixes):

1. Adds `upstream` (safe-global) and fetches base tag.
2. Creates `<id>-staging` from the base tag.
3. Adds `upstream-staging` (protofire/private-safe-wallet-monorepo) and creates `remote-staging` from its `staging`.
4. Patches `apps/web/package.json` to install `safe-network-config` from your feature branch (only if `--snc-branch` was given).
5. Patches `.husky/{pre-commit,commit-msg,pre-push}` to be dash-compatible.
6. Runs `yarn install`, `yarn localhost:config-update`, then verifies `node_modules/safe-network-config/networks/<id>/` exists.
7. Writes `apps/web/.env` with `TEMPLATE_ID`, `NEXT_PUBLIC_DEFAULT_TESTNET_CHAIN_ID`, `NEXT_PUBLIC_GATEWAY_URL_STAGING`.
8. Runs `prebuild-config.js --network <id>` and `prebuild-patch.js`.
9. Removes `prebuild*.js`, `safe-network-config` dep (best-effort), and the `prebuild` + `localhost:config-update` scripts.
10. Squashes everything into a single commit on `<id>-staging` on top of the base tag.

Read references/rollout-patches.md before debugging if any step fails — every error mode I've seen is explained there.

### 2.3. Clean up empty patches

`prebuild-patch.js` sometimes produces a 0-byte `.yarn/patches/<pkg>-*.patch` and inserts a `resolutions` entry pointing at it. Local `yarn install` tolerates this; CI's `yarn install --immutable` rejects it. Always run:

```bash
.claude/skills/safe-network-rollout/scripts/cleanup-empty-patch.sh --commit
```

This deletes empty patches, reverts the affected `package.json` deps and `resolutions`, regenerates `yarn.lock`, and commits. If no empty patches exist, the script no-ops.

### 2.4. Confirm `safe-network-config` is fully gone

After the rollout copies icons and runs the prebuild scripts, the `safe-network-config` dep is no longer needed (and on a public fork, CI can't fetch it without SSH keys → `Permission denied (publickey)`). Verify nothing references it:

```bash
grep -rn 'safe-network-config' --include='*.json' apps/ packages/ ./*.json | grep -v node_modules
# Expected: no matches.
```

If matches remain, edit them to drop the dep / resolution and re-run `yarn install` + `yarn install --immutable`.

### 2.5. CI-equivalent verification

Mirror what CodeBuild does:

```bash
.claude/skills/safe-network-rollout/scripts/ci-verify.sh
```

All four steps must be green before pushing:

| Step | What it catches |
| --- | --- |
| `yarn install --immutable` | empty patches, lockfile drift, missing private deps |
| type-check                 | template config typing, network field shape |
| lint                       | ESLint regressions (rare) |
| build (`yarn fetch-chains && next build`) | gateway reachability + full Next.js prerender |

### 2.6. Push

```bash
git push origin <id>-staging
```

CodeBuild will build from this branch and deploy to staging.

## Iterating on a logo or config after rollout

If the staging UI looks wrong (icon missing, dimensions off, palette wrong), fix the source first, then re-flow:

1. Edit `networks/<id>/{config.json,public/images/*.svg,*Palette.json}` in this repo.
2. Push to `feat/<id>-network` (or directly to `main` if it's already merged).
3. In the wallet clone: revert local edits, `git checkout <base-tag>`, re-run `scripts/rollout-wallet-fork.sh`.
4. `cleanup-empty-patch.sh` → `ci-verify.sh` → push.

For a **logo-only** fix where you don't want a full rollout, you can also patch the live wallet copy directly:

- `tmp/<wallet-fork>/apps/web/public/images/logo*.svg` — replace the file
- `tmp/<wallet-fork>/apps/web/src/config/templateConfig.ts` — edit `LOGO_DIMENSIONS` if needed

Commit on the existing staging branch and push. Mirror the same fix in `networks/<id>/` upstream so the next rollout doesn't regress.
